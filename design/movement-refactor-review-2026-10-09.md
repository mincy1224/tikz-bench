# 移动、矩阵与交互重构审查记录

日期：2026-10-09。范围为普通节点、路径、分区矩形、矩阵和组合。Forest、PGFPlots、Circuitikz 高级反向编辑不属于本轮扩展范围。

## 第一阶段：统一几何、移动与事务

语义结果新增 `PlacementGeometry`：真实放置锚点、父级变换、父对象与子对象归属。增量检查点和效果回放同步维护这些信息。矩阵 `at` 对应 `matrix anchor` 指定的锚点，不是视觉包围盒中心，参见 [PGF 矩阵规则](https://tikz.dev/tikz-matrices)。

鼠标、方向键、位置字段、对齐和分布共用 `OperationPlan`。父级逆线性变换将世界位移转换为局部位移；所有对象从同一基线规划，一次性写回。包围盒只用于对齐、吸附、尺寸与命中。命名端点保持引用，矩阵单元格名称纳入依赖查询。不能安全改写的表达式拒绝整次操作。

移除旧移动实现中的临时 `\path` 父级探测、矩阵中心替代放置坐标、逐对象移动及局部成功分支。可合并的开头数值 `shift` 合并，跨越用户旋转／缩放的平移不合并。编辑器创建的中心旋转支点随图形移动，外部支点保持原有语义。

事务校验文档、活动图形、源码版本和对象范围，连续操作只提交一次。取消恢复基线源码和就绪画面，拒绝迟到预览。方向键默认 1pt、Shift 10pt，与网格无关；事件按动画帧累计。提交保留操作补丁供增量渲染使用；撤销清除补丁。预览不进入保存或持久化历史。

新增世界位移断言覆盖四种矩阵锚点、显式／隐式位置、变换父级、相对定位、反向移动、锚定连接和增量后缀复用；测试不只检查生成字符串。

## 第二阶段：矩阵和组合

矩阵整体选择与拖动、双击单元格编辑、Esc 返回整体／清除选择使用显式编辑状态。单元格禁止独立移动和缩放，保留原有行列选择、添加与删除操作。普通对象、矩阵和组合共享缓存的能力查询。

矩阵默认尺寸调整修改布局间距或单行／单列的尺寸约束，保留字号与线宽；整体缩放另行缩放字体、线宽、尺寸约束及结构化行列局部间距。低于内容尺寸时拒绝写回并说明原因。矩阵的 `anchor`、`matrix anchor`、名称、行列内容与连接不被替换。

组合使用完整世界联合边界，含未绘制外框的矩阵单元格。组合内节点／矩阵的布局不会自动跟随父级坐标变换缩放，因此核心单独调整布局并恢复期望中心。无法达到请求尺寸时拒绝整次操作。矩阵和混合组合尺寸修改产生局部补丁，保留增量解析能力；缩放后仍可取消组合并保留继承作用域。

增量解析器同时修复多个补丁的范围映射：旧范围始终基于同一源码，不能把已移动的偏移继续与旧范围比较。新增“前方插入 + 嵌套完整节点替换”回归，并比较增量与完整语义／SVG 结果。

矩阵整体旋转没有新增独立能力；可使用父组合变换。任意宏或不可逆变换也不会被强行改写。

## 第三阶段：性能、格式与保存

保留现有解析、语义、SVG、保存队列及增量设施。安全整体移动使用显示层预览，提交一次；存在不能刚性移动的依赖时使用统一语义更新。移动、缩放、旋转执行器从大型拖动控制器中抽出。移除悬停时无条件预热整份文档；就绪场景上的选择不再重复求值。

提交后的画布继续使用稳定坐标原点。若每次移动都按最新外边界重新基准化 `viewBox`，所有未移动对象的 SVG 坐标和命中区也会改变，导致整幅画面重写。独立导出仍根据当前源码和实际范围生成。

主场景 SVG 允许超出原有范围绘制，裁切由画布视口负责；新增截图像素回归，验证移出原范围后图形实际可见，避免仅靠 DOM 包围盒漏检裁切。

右栏保留图形／文字入口，使用共享字段、能力描述和事务。实际宽高与中心位置独立于最小尺寸、文本宽度；数值写回后检验实际尺寸，不把受限值伪装成已成功。字号、单位、步进、重置、Enter／Esc／失焦和组合输入使用统一逻辑。矩阵／组合的混合字号、字体、颜色和线宽显示多个值；矩阵外框颜色不冒用单元格颜色。格式刷跳过无法确定的多值格式。

有界保存队列保留。新增失败后排队调用正常结束、可重试最新草稿的回归；浏览器验证预览无保存、当前草稿导出、失败重试、撤销后保存一致性，以及旧慢请求不能覆盖新项目。

## 验证环境与方法

- Windows，AMD Ryzen 9 8945HX，32 逻辑核心，约 31.8GiB RAM；Node 22.22.0。
- 浏览器：Microsoft Edge 154.0.4258.62，headless，生产构建，单 worker。性能测试期间不并行运行单元测试或构建。
- 1000 个逻辑对象混合节点、圆、矩形；移动组含 6 个节点和 5 条命名锚点连接。另测同时移动 6 个独立对象。
- 选择响应测 pointerdown 至第二次动画帧，共 12 个样本。拖动持续约 1.2 秒，每帧发出 4 个 pointermove，统计动画帧间隔；记录开始、释放至就绪、长任务和解析／计算计数。
- `TIKZ_PROFILE_VERBOSE=1 TIKZ_PROFILE_BUILD=1` 仅用于诊断，CPU 采样和非压缩标识会影响时延，不用于生产性能验收。默认构建保留 p95 阈值检查。
- 5000 对象为压力测试，检查提交、取消、撤销和无异常，不承诺达到 1000 对象的流畅度门槛。

### 生产性能结果

| 场景 | 选择响应 p95 | 拖动帧间隔 p95 | 开始耗时 | 释放至就绪 |
| --- | ---: | ---: | ---: | ---: |
| 1000 对象，移动 6 节点＋5 连接的组 | 59ms | 9ms | 5ms | 786ms |
| 1000 对象，移动 6 个独立对象 | — | 9ms | 11ms | 1114ms |

选择和持续拖动达到本轮 100ms／20ms 门槛。预览期间解析、属性查询和计算任务计数为零，没有源码提交。释放后的增量计算分别为 297ms／279ms：组移动复用 989 个未修改语句，独立对象移动复用 994 个；剩余等待主要在 React 提交和 DOM 更新。释放阶段仍出现 663ms／988ms 长任务，**不是全流程即时响应**；这一限制需要后续进一步优化场景订阅和命中层更新。

5000 对象压力回归验证提交、撤销和取消成功；选择 p95 为 425ms、拖动帧间隔 p95 为 33ms，超出常用大图门槛，不承诺这一规模流畅。该压力测量在最终提交增量补丁优化之前执行，作为压力记录，不与最终 1000 对象结果混用。

## 重装

本轮没有数据库结构变更，不创建新库，不删除旧库，不替换 TeX Live，也无需手动卸载程序。提交推送到自己的 GitHub 仓库后执行：

```bash
cd ~/tikz-bench &&
git pull --ff-only &&
nvm use 22 &&
bash install.sh &&
tikz-bench start &&
tikz-bench version &&
tikz-bench status
```

```bash
curl -fsS http://127.0.0.1:5173/api/health
tikz-bench logs
```

安装器沿用 `/etc/default/tikz-bench` 和当前数据库配置。Git commit 不会自动推送。
